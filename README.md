# markockiadam.com

My personal website: a digital business card and portfolio.
Plain HTML, CSS and JavaScript. No build step. Hosted free on GitHub Pages.

## Change the text

**Almost everything lives in [`content.js`](content.js):** projects, links, journey, and all three languages (EN / PL / FR).
Lines marked `// TODO` still need real info.

- **New project:** copy one `{ ... }` block in `projects` and edit it.
- **Photo:** put a square image in `assets/` (e.g. `assets/adam.jpg`) and set `photo: "assets/adam.jpg"`.
- **Email:** set `email:`. The "Email me" button only appears once this is set.
- **Icons:** `trophy, globe, block, book, heart, chart, star, flag, crown, pick, grid, mail`.

## Run it locally

```bash
python3 -m http.server 8000
```

Then open http://localhost:8000.

## Publish on GitHub Pages

1. Merge into `main`.
2. Repo **Settings → Pages → Build and deployment → Deploy from a branch → `main` / `(root)`**.
3. **Custom domain:** enter `markockiadam.com` (do this once the card.co subscription ends; GitHub adds a `CNAME` file) and tick **Enforce HTTPS** once it's available.

## Two styles: PIXEL and ATLAS

The site has two looks that show the same content (everything still comes from `content.js`):

- **PIXEL** — the playful pixel sky, hotbar and treasure chest.
- **ATLAS** — an analyst console: world map, link graph, data tables, GitHub signals,
  activity timeline and a redacted "dossier" CV you can declassify. Press **⌘K** (or **/**) to search.

First-time visitors pick one; the choice is remembered. Switch any time with the **PIXEL | ATLAS**
toggle in the top-right. Share a specific style with `?skin=atlas` or `?skin=pixel`
(e.g. `markockiadam.com/?skin=atlas#cv` opens the console with the CV declassified).

Files: `css/atlas.css`, `js/atlas.js`, `js/worldmap-data.js` (generated by `scripts/build-worldmap.mjs`).

## GitHub heatmap (updates itself)

`.github/workflows/contributions.yml` runs twice a day. It saves your contributions to
`data/contributions.json` and commits it, so the heatmap is always fresh even if the live
API is down. The page shows the saved data instantly, then swaps in live data if available.
Run it by hand any time: **Actions → Update GitHub heatmap → Run workflow**.
(Scheduled runs start once this is merged into `main`.)
